# Отчёт по доработке Seren Lottery Chain

Дата проверки: 23 июля 2026 года.

## 1. Hero и доверие

- Обновлены основной заголовок, описание, CTA и риск-дисклеймер во всех восьми локалях.
- Добавлены шесть trust-бейджей: Polygon Mainnet, верифицированный контракт, Chainlink VRF v2.5, 10 выигрышных билетов, прямой claim и non-custodial модель.
- Сохранены исходные Banner, логотип и фирменная тёмно-синяя/фиолетовая визуальная система.

## 2. Прогресс фонда

- Добавлен `PoolProgressIndicator`, который использует только значения активного раунда, прочитанные через wallet RPC.
- Расчёт выполняется на `bigint` в basis points, визуальный процент ограничивается 100%, превышение цели отображается отдельно.
- Реализованы состояния: кошелёк не подключён, подключение, неверная сеть, загрузка, данные получены, RPC/контракт недоступен.
- Показывается номер последнего успешно прочитанного блока. Демонстрационные суммы не используются.

## 3. Seren Oracle

- Добавлен развлекательный Oracle с доступным модальным окном, focus trap, Escape/закрытием, возвратом фокуса и блокировкой фоновой прокрутки.
- Без кошелька результат создаётся через `crypto.getRandomValues`; с подключённым адресом — детерминированно по нормализованному адресу и UTC-дате через Web Crypto SHA-256.
- Oracle не подписывает сообщения, не делает транзакций и не обращается к RPC или серверу.
- В каждой локали доступно 50 сочетаний сообщения и символа; поддержаны Web Share и копирование.

## 4. Анимации и производительность

- Добавлены декоративные POL-монеты с одним passive scroll listener и одним `requestAnimationFrame`-циклом без React state на скролле.
- Есть cleanup, облегчённый режим для устройств с малым количеством аппаратных потоков и отдельное поведение для `prefers-reduced-motion`.
- Декорации скрыты от accessibility tree; текст POL рисуется CSS-псевдоэлементом.

## 5. Покупка, победители и активность

- В карточку раунда добавлены состояния реальных данных, прогресс и постоянное предупреждение о seed phrase/private key.
- Существующий contract quote → simulation → wallet write → receipt flow сохранён.
- После успешной покупки показывается диапазон ticket ID, если он присутствует в декодированном событии контракта.
- В результатах уточнена связь ticket ID и адреса владельца, добавлены ссылки на контракт/PolygonScan.
- В активности добавлены блок, timestamp и сокращённый hash транзакции.
- На мобильных устройствах sticky CTA появляется только при наличии настоящей цены билета и когда основная карточка покупки вне viewport.

## 6. Локализация и SEO

- Новые пользовательские тексты добавлены для `en`, `ru`, `es`, `zh`, `hi`, `ar`, `fr`, `pt`.
- Проверен Arabic RTL, включая расположение кнопки закрытия Oracle.
- Публичный marketing-контент остаётся server-rendered на всех восьми маршрутах.
- Существующие правила noindex для preview/development и production-only canonical/hreflang сохранены.

## 7. Безопасность интеграции

- ABI, адрес контракта и chain ID не изменялись.
- Публичные lottery-взаимодействия продолжают использовать Polygon Mainnet 137 и адрес `0x0C59B1c64925425AB307Cc19A92AD176E0709360`.
- Все contract reads/simulations/writes/receipts/event decoding остаются на `viem` и wallet-only provider.
- Ни одной записи в Polygon Mainnet во время разработки или тестирования не выполнялось.

## 8. Автоматические проверки

- `npm run typecheck` — успешно.
- `npm run lint` — успешно.
- `npm run test` — 14 файлов, 41 тест, все успешно.
- `npm run build` — успешно; восемь locale-страниц сгенерированы как SSG.
- Добавлены тесты для bigint-прогресса, состояний индикатора, Oracle, детерминированности, motion cleanup, локализации и отсутствия демонстрационных значений.

## 9. Ручная браузерная проверка

- Проверены ширины 320, 360, 390, 430, 768, 1024, 1440 и 1920 px.
- На всех ширинах горизонтальное переполнение равно нулю; минимальная высота видимых кнопок и button-like ссылок — 44 px.
- Проверены русская LTR и арабская RTL версии, открытие/закрытие Oracle, удержание фокуса и адаптивная геометрия hero.
- Реальные connected/wrong-network/write сценарии в браузере не запускались, чтобы исключить mainnet-транзакции; эти ветки покрыты моками и тестами.

## 10. Известные ограничения

- Без подключённого wallet provider сайт намеренно не показывает цену, фонд, результаты или event history и не подставляет примерные значения.
- `npm install` сообщает о трёх high-severity уязвимостях в дереве зависимостей; автоматический `audit fix --force` не применялся, чтобы не внести потенциально несовместимые обновления.
- Production deployment не выполнялся: для него требуется отдельное явное разрешение владельца проекта.
